## Blocking issues (must fix before acceptance)

### B1. The session ends at 15 minutes, although the refresh token is valid for 30 days
- **Page:** every signed-in page. All viewports, locales, themes.
- **Seen:** at the 15-minute mark of one continuous browser session, pressing `g h` on Needs landed on `/ar/sign-in?next=%2Far%2Fgoteav%2Fhandoffs`. Reproduced on a plain load: with only `hub_refresh` left in the jar, `GET /ar/goteav/tasks` went to sign-in with **no refresh call at all** (logged: 0 calls to `/auth/refresh`). The same cookie then answered `POST /api/v1/auth/refresh` with 200, so nothing was wrong with the session.
- **Cause:** `apps/api/src/modules/identity/presentation/cookies.ts:44-47` scopes `hub_refresh` to `Path=/api/v1/auth/refresh`, with `ACCESS_TTL_SEC = 15 * 60`. `apps/web/src/middleware.ts:23` looks for `hub_access` or `hub_refresh` on page URLs, where the browser never sends the refresh cookie. Once `hub_access` expires, middleware sees a signed-out visitor before the client's 401 refresh can run. A tab survives only if an API call happens to hit the 401 first, so it will look intermittent.
- **Why it matters:** any reload, new tab, deep link or client navigation after a coffee break throws the owner to sign-in. It also interrupts docs/15 §1's demo, which runs longer than that with a page open.
- **Fix:** keep the narrow refresh path and add a non-secret marker cookie (`hub_session=1`, `Path=/`, same `maxAge` as refresh), set in `setSessionCookies` and removed in `clearSessionCookies`. Middleware checks that. Add an e2e test: delete `hub_access`, reload, expect to stay on the page and see one refresh.

### B2. Card text is shown as raw Markdown collapsed into one paragraph
- **Page:** card sheet, all types except Plan (Decision and Redesign seen, code path is shared). Decisions' lead card. 1440 and 390, ar and en, light and dark.
- **Seen:** GTV-2's Details, the text the owner reads before deciding on the hotel supplier, is one unbroken block of more than 30 lines containing literal `##` headings and ` - ` bullets (`sheet-from-today-1440-ar-dark.png`, `sheet-decision-390-ar-light.png`). GTV-309 reads `# Ticket with a code ## Idea Trial of… ## Key decisions - Layout and…` with literal backticks (`sheet-redesign-1440-en-light.png`). The Decisions lead card starts its excerpt with `## الملخص`.
- **Where:** `apps/web/src/components/cards/card-sheet.tsx:590-592` renders `<Bidi>{card.body}</Bidi>` in a `<p>`. `apps/web/src/components/decisions/on-the-table.tsx:140-142` does the same with `line-clamp-2`.
- **Why it matters:** this is the main read surface of Hub and real bodies are Markdown (imported decisions, version READMEs). The app already has the right component, and the Plan sheet using it reads well (`stub-sheet-plan-1440-ar-dark.png`).
- **Fix:** `MarkdownView` in the sheet with `dir="auto"` on the body. For a clamped excerpt, strip Markdown to plain text first, or show the first paragraph under the first heading.

**M3. A deadline two weeks away reads as today.** Today, Decisions, any use of `when()`. All modes.

**M4. Decisions' lead card cannot hold a real decision.** Decisions, 1440 ar dark, also en and 768. Phone is better, since pros and cons fold.

`on-the-table.tsx`. **Fix:** show recommended options first, at most 3, and fold the rest under «و12 خيارًا آخر». Clamp pros and cons per option with a disclosure at every width, as the phone already does. Decide whether two recommendations are valid data, and if so, fill neither or say why.

**M5. Tasks list opens on finished work.** Tasks list, default view on phone (390), and list view at all widths.
Default sort is priority, across all statuses. Row statuses at 390 ar: done ×4, ready ×2, done ×5, ready. The first Claim on the phone is at y ≈ 830, after four finished tasks (`hub-tasks-390-ar-dark.png`, `tasks-list-1440-ar-dark.png`). The board does this properly, folding Done into a rail with 35. `apps/web/src/components/tasks/list.tsx`, `tasks-page.tsx`. **Fix:** open statuses first and done last by default (or Done off behind a filter chip), with priority inside that. An explicit column sort can still mix them. Also do not offer a priority dropdown on a done row.

**M6. "12 ready for your roles" is not true for the owner, and Tasks has no filled button.** Tasks and Today, sidebar badge. All modes.
All 12 are routed to Backend, and the owner's roles are owner, pm and accountant. Subtitle, sidebar and Today's «جاهزة لأدواري» all say 12. `primaryKey` correctly finds none in his role, so no Claim is filled, unlike the lab (matrix: Tasks' filled list is empty, lab has `احجز`). `apps/web/src/components/tasks/tasks-page.tsx:224-228` and the `GET /tasks/ready` scope behind `useReadyTasks`. **Fix:** decide once. If managers legitimately see all ready work, the words should say «12 مهمة جاهزة في المشروع» and the first claimable row should be filled. If not, scope the endpoint to routed roles. **M7. The first open of a sheet does not land on its primary action.** Any list, 1440 ar and en; first open of each card.
Lab: `j`, `Enter` → focus on the filled `قرّر` button. Hub: focus on the dialog container (`DIV role=dialog`), so reaching Decide takes 3 Tabs through More and Close. Second open of the same card, now in cache: `احجز`, correct. So this is a port regression from async data: `onOpenAutoFocus` runs before the card exists, and neither `[data-sheet-primary]` nor `[data-sheet-close]` is there yet.
`card-sheet.tsx:676-684`. **Fix:** render Close outside the loading branch, and when the card arrives move focus to `[data-sheet-primary]` if focus is still on the container.

**M8. `/workspaces` has no awaiting counts.** `/workspaces`, all modes.
docs/15 §5 and docs/09 §2 ask for them. Goteav has 9 waiting and the card shows nothing, only a blank third of the card (`hub-workspaces-1440-ar-dark.png`). The UI handles the field (`projects-page.tsx:60`); a search finds no `awaitingCount` anywhere in `apps/api`.
**Fix:** add it to `GET /workspaces`. It is also the one thing that would justify this page for a member with several projects.

**M9. No styled 404 and no error boundary.** Any unknown URL; any render crash. All modes.
`/ar/goteav/nosuchview` and `/en/nope/deep/path` show Next's default white page: English only, ignoring dark theme and `dir` (`route-_ar_goteav_nosuchview.png`). There is no `not-found.tsx`, `error.tsx` or `global-error.tsx` under `src/app`, and no `ErrorBoundary` in `src`. The lab puts every page behind a boundary (README, "Views"), so a throw in one component now takes down the whole shell. I read this from the code and did not cause a crash. The unknown-project state is good, by contrast: «لست عضوًا في هذا المشروع» with a way out.
**Fix:** `[locale]/not-found.tsx` and `[locale]/[ws]/error.tsx` using `ErrorState`, plus a boundary around each page inside the shell so the sidebar survives.
